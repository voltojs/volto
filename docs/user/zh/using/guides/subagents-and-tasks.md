# 子代理与后台任务

> 读完你会：知道什么时候该派子代理、它能做什么不能做什么，以及怎么加一个自己的子代理类型。

## 子代理是什么

主 agent 可以调用 `task` 工具，把一件独立的子任务派给一个**子代理**（另一个 agent 实例）。子代理有自己的一段上下文，**看不到你与主 agent 的对话**——所以派发的说明必须自包含。

好处是隔离：一次大范围搜索、一个独立的重构，不会污染主对话的上下文。

## 派发时能控制什么

| 参数 | 作用 |
| --- | --- |
| `message` | 子任务说明。自包含；写清范围、深度、期望产出大小 |
| `subagent_type` | 用哪个子代理定义（不填用 `general-purpose`） |
| `acceptance` | 验收标准。写了就一定会被判定；不达标默认自动返工一次。见下文「验收与返工」 |
| `model` | 这一趟用哪个模型路由档位（填档位 id，不是模型名） |
| `permission` | 子代理的权限档：`read-only` / `ask` / `auto` / `full`，**只能更窄，不能更宽** |
| `tools` | 工具白名单，与父会话的工具集取交集——只能收窄 |
| `max_iterations` | 这一趟的循环次数上限 |
| `title` | 界面上显示的标签（不发给子代理） |
| `system_prompt` | 追加在子代理角色提示之后的补充说明 |
| `run_in_background` | 立刻返回一个任务 id，不阻塞主对话 |

**权限与工具都只能收窄。** 想让子代理做父会话做不到的事是不可能的：更宽的权限会被拒绝，并回给你可用的档位列表。这条设计是有意的——子代理不能成为绕过审批的后门。

## 验收与返工

派发时可以给子代理定一条验收标准（`acceptance` 参数）。写成能逐条核对的标准，比如「测试全部通过并附上输出」「生成的文件包含字段 a 与 b」，不要写「做好一点」这类无法判定的愿望。标准最长 2000 字符。

写了标准就一定会被判定，流程是固定的：

1. **子代理看得到标准。** 标准附在派发说明里，子代理知道完成后会被照此验收。
2. **完成后由另一次模型调用判定。** 判定看子代理实际的调用与结果证据，不看它「我做完了」的声明；证据不足以确认的标准会判为不通过。
3. **首次不通过，自动返工一次。** 默认允许一次返工：失败原因与修复建议发回**同一个子会话**，子代理在已有改动的基础上继续做，不会从零重来。
4. **返工仍不通过，这次派发按失败返回。** `task` 调用结果为失败态，正文逐条列出失败原因，主 agent 据此决定下一步。返工后通过则按已验收返回。

判定器自己跑不起来（超时、输出无法解析）不算实质失败：不返工，标记为「未能验收」。子代理自己崩溃同样按失败处理。

### 徽标含义

写了标准的派发，卡片上会多一个判定徽标；没写标准则没有徽标，行为与从前一致。

| 徽标 | 含义 |
| --- | --- |
| 已验收 | 达标（可能是返工后达标） |
| 未通过（N 次） | 跑了 N 次仍未达标（N 是子代理运行次数，默认预算下最大为 2 = 首轮 + 一次返工） |
| 未能验收 | 判定器自身出错，工作是否达标没有结论 |

「未通过」与「未能验收」是琥珀色警告标记，**鼠标悬停可看原因**；失败原因也写在工具结果正文里。点开派遣卡片可以进入子会话，看到返工那一轮的完整对话。

### 后台任务的判定在哪看

带标准的后台派发（`run_in_background: true`），判定出现在三处：

- **派遣卡片**：任务结束时徽标即时补上，不用刷新；
- **`task_output` 结果行**：主 agent 取结果时，该行带同样的徽标；
- **完成通知**：即使主 agent 一直没取结果，后台任务完成通知的正文也会在 `[background task … finished]` 标题之后，以 `[verification: …]` 一行开头（如 `[verification: failed after 2 attempts]`），判定不会悄悄丢失。

## 后台任务

`run_in_background: true` 时，`task` 立刻返回任务 id，主对话继续。之后：

- 用 `task_output` 取结果（可以反复取，直到它结束）；
- 后台任务结束后会有事件推给界面；右侧面板的「任务」页签里能看到进度与结果；
- 子代理失败不会拖垮主对话——错误作为结果返回。

适合：跑一次很长的测试、并行搜索多个方向。

## 会话切换与右侧面板

右侧面板的状态**按会话记忆**：每个会话各自记住自己的页签（含子代理 / 计划）、活动页签与展开 / 收起。切换到别的会话时恢复该会话自己的状态；从未打开过的会话默认收起、空页签，因此不会看到上一个会话的子代理面板。回到旧会话时，它的子代理 / 计划页签与展开状态原样恢复。状态保存在本设备，刷新后仍在。留在当前会话时，新产生的后台任务或新一轮计划仍会自动打开对应页签。

## 嵌套深度

默认最多两层：主 agent → 子代理。子代理再往下派会被拒绝。这个上限防止「agent 开 agent」无限繁殖——真需要更深，把大任务拆成几次顺序派发。

## 自定义子代理类型

在下面两个目录放 Markdown 文件即可，一个文件一个类型：

| 目录 | 作用范围 | 优先级 |
| --- | --- | --- |
| `~/.volto/agents/` | 用户级，所有项目可用 | 低 |
| `<工作区>/.volto/agents/` | 项目级，只在该工作区可用 | 高（同名覆盖用户级） |

文件正文是子代理的系统提示，元信息写在文件里（名称、描述、工具、模型、权限）。两个内置类型 `general-purpose` 与 `explore` 始终可用，且**不可删除**——编辑它们会在用户级生成一个同名覆盖文件。

「设置 → 子代理」里能看到合并后的列表，标出每个条目的来源（项目 / 用户 / 插件 / 内置）以及是否被同名条目覆盖。

## 出问题怎么办

- **子代理做错方向** → 多半是 `message` 不够自包含；它看不到上下文，主对话里的约定它一无所知。
- **子代理什么工具都没有** → `tools` 传了空数组，或它需要的能力父会话没有。
- **派发被拒，提示权限过宽** → 把 `permission` 改窄；它不能超过父会话这一档。
- **后台任务一直没结果** → 用 `task_output` 查它的状态；长任务可能只是还在跑。
