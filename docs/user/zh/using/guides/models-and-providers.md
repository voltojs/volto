# 模型与供应商

> 读完你会：配好供应商、理解模型路由档位，并能判断「模型没响应该怪哪一层」。

## 供应商的两种类型

| 类型 | 什么时候用 | 需要填什么 |
| --- | --- | --- |
| 内置目录（catalog） | 厂商在目录里（Anthropic、OpenAI 及主流兼容厂商） | API Key；模型从目录选，能力（上下文窗口、是否支持图片/推理）自动带出 |
| 自定义（custom） | 自建网关、私有部署、目录里没有的 OpenAI 兼容端点 | base URL、API Key、模型 ID，能力字段需要自己填 |

自定义类型的模型 ID 就是你端点接受的那个字符串；内置目录类型里选的是目录自己的模型 code。

## 密钥怎么存

- API Key **加密后**写在 `~/.volto/config.json` 的 `providers` 分区（`apiKeyEnc`）。
- 任何接口响应都不会返回明文；唯一的例外是网关内部构建模型连接时读一次。
- 所以：**手改 `apiKeyEnc` 写明文无效**，加新供应商请走界面或 `POST /providers`。

## 模型字段

| 字段 | 作用 | 不填时 |
| --- | --- | --- |
| `contextWindow` | 上下文窗口大小，决定用量条与压缩时机 | 用量条不显示百分比 |
| `maxOutputTokens` | 单次调用最多生成多少 token | 用provider 的默认值 |
| `reasoning` | 这个模型是否支持推理/思考 | 内置目录供应商：跟随目录；自定义供应商：视为不支持 |
| `input` | 输入模态，例如只收文本 | 内置目录供应商：跟随目录；自定义供应商：未知（仍放行图片，让厂商报错而不是让工具消失） |
| `protocol` | 该模型走哪种线上协议 | 跟随供应商的默认 |
| `thinkingLevelMap` | 按档位记录「推理等级 → 发给端点的参数值」的覆盖表，语义见下面「推理等级」一节 | 跟随目录；自定义供应商没有映射到的档位按档位名本身发送 |

## 推理等级

在「设置 → 模型配置」里展开某个模型那一行，「推理等级」一节可以按模型修改每个推理档位实际发给端点的参数值。打开「启用推理等级覆盖」开关才能编辑这些行。

需要它的典型场景是兼容端点不接受标准档位名——比如要 `enabled` / `disabled` 而不是 `high` / `off`，或者某个档位在该模型的内置目录里根本没有列出。

档位全集是七个：`off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`。每一行有三种状态：

| 行的状态 | 含义 |
| --- | --- |
| 填了值 | 该档位可用，并且就按你填的这个字符串发送。 |
| 勾了「不支持」 | 明确声明该档位不可用：它会从对话输入框的推理选择器里消失；仍然指名要它的请求会被明确拒绝并报错，而不是悄悄换成别的档位。 |
| 留空 | 继承默认——内置目录供应商继承目录自己的值；自定义供应商里端点能用的档位按档位名本身发送，`off` 则完全不发送推理参数。 |

- **新增档位会自动带上值。** 在「档位」列选一个档位或点「添加档位」时，值输入框会先填上档位名本身（多数模型的 `xhigh`、`max` 没有内置映射）。把框清空就又回到继承默认；`off` 行在没有映射时显示「关闭思考」。
- **关掉总开关等于删除该模型的全部覆盖**，不是存着不用；再打开时会恢复你关掉之前的内容。收起再展开这一行，读到的是已保存的配置——仅限保存之后；行内尚未保存的修改会丢失。
- **模型的「推理」勾选还没打开时改了档位值，会自动帮你开启推理**，并提示「已自动开启推理」——否则这个设置会被存下来却永远不生效。推理未开启期间，这一节还会显示「开启推理后生效」。

两条边界值得知道：

- **改的是值，不是字段。** 填进去的值发进该端点协议本来就在用的那个推理参数（`reasoning_effort`、`thinking`、`reasoning.effort` 等），这里不能改名也不能改结构。
- **数值型 token 预算不是档位值。** 档位只能映射成文本值，限制思考 token 数量在这一节里配不了。

输入框里的占位值就是这个模型当前真正生效的值，所以不保存也能读出实际会发出去什么。

## 模型路由档位

「设置 → 模型路由」里可以定义若干档位（出厂模板是 premium / fast / economy），每档指向一个「供应商 + 模型」。给子代理派任务时可以指定用哪一档。

- **档位没指派目标**（target 为 null）不是错误——派发时退回父会话正在用的模型。
- 删除一个仍被子代理引用的档位会被拒绝（409），先改子代理再删。

## 连通性探测

供应商卡片上有「测试路由」按钮：它检查当前配置（模型能否解析、Key 是否存在、协议是否可知），结果显示「路由可用」或「路由不可用：&lt;原因&gt;」。它不会真的向供应商发请求；第一次真实请求发生在对话里。换 Key、改 base URL 之后先测一次，比在对话里撞错误快。

## 起标题用什么模型

「设置 → 通用设置 → 标题模型」可以指定一个便宜的小模型专门给新会话起标题。不选则直接截取首条消息。

## 出问题怎么办

- **401 / 403** → Key 无效或没有该模型的权限；先点「测试路由」。
- **404 / 模型不存在** → 自定义供应商的模型 ID 拼错，或内置目录里该模型 code 变了。
- **回复很慢或立刻截断** → 检查 `contextWindow` 与 `maxOutputTokens` 是否填得比实际小。
- **图片发不出去 / 模型说看不到图** → 该模型的 `input` 没声明图片，或被显式声明成只收文本。
- **设好的推理档位不起作用** → 先确认该模型的「推理」已勾选、该档位没被勾成「不支持」；不支持的档位会在报错里点名拒绝，而不是被换成别的档位。

字段全集见 [配置文件参考](../reference/config.md)。
