# 一轮对话发生了什么

> 读完你会：知道消息发出去之后，哪些环节可能卡住、卡住时该看哪里。

## 一句话版本

你发一句话 → 组装上下文 → 问模型 → 模型要么回答要么要工具 → 执行工具并把结果塞回去 → 再问模型 → ……直到模型不再要工具，这一轮结束。

## 展开版本

```text
你按下回车
   │
   ├─ 组装上下文：系统提示 + 工具说明 + 项目指令 + 历史消息 + 你的新消息
   │                 （静态部分在前，动态部分在后，为了命中缓存）
   │
   ├─ 问模型 ──► 模型流式吐字 ──► 界面逐字显示
   │                │
   │                └─ 模型说「我要调用 bash」
   │                      │
   │                      ├─ 这个工具对模型可见吗？（不可见 → 模型根本不会提）
   │                      ├─ 这个调用被允许吗？  （需要问 → 弹审批卡，卡住等）
   │                      ├─ 执行（在沙箱里）
   │                      └─ 结果塞回上下文 → 再问模型
   │
   └─ 模型不再要工具 → 这一轮结束
```

## 几个容易被误解的点

**「工具不可见」不是「工具被拒」。** 不可见是装配阶段就决定的（这台机器上没有 shell，`bash` 就不会出现在模型的工具清单里）；被拒是执行阶段才发生的（用户在审批卡上点了拒绝）。前者模型压根不知道该用，后者模型知道自己被拒了，会换做法。

**拒绝不会让对话崩掉。** 拒绝会作为一条「工具结果」回给模型，它会尝试别的路径。

**上下文会被压缩。** 对话长了以后，较早的消息会被折叠成摘要，最近的保留原文。压缩是自动的，也可以 `/compact` 手动触发。

**工作目录与分支会以提醒的形式注入。** 你在会话中途 `cd` 到别的目录，下一轮模型就知道——它不需要你重新说一遍。

## 卡住时看哪

| 现象 | 看的环节 |
| --- | --- |
| 一直没有输出 | 模型连接（供应商/网络） |
| 一直在「思考」却没动作 | 模型在生成很长的推理，或工具调用参数不合法在重试 |
| 停在审批卡 | 在等你点 |
| 反复调用同一个工具 | 工具返回值没给足「已完成」的信号，或描述没说清边界 |
| 忽然开始忘事 | 上下文被压缩了，早期细节变成了摘要 |
