# 安全模型（用户版）

> 读完你会：知道这些边界实际挡得住什么，以及哪些事它根本不承诺。

## 一句话

沙箱与审批防的是**模型犯错**——手滑删错文件、在错误的目录里跑命令。它们**不承诺**防住**模型被诱导**：仓库里的一个恶意 README、网页上一段精心构造的指令，都可能让 agent 做出你不想做的事。

这个区分不是免责声明，它决定了你该怎么用它。

## 实际挡得住的

| 机制 | 挡什么 | 边界在哪 |
| --- | --- | --- |
| 沙箱 | 写工作区外的文件、破坏系统目录、在只读档下写盘 | 是系统调用级隔离；「完全」档没有 |
| 审批 | 需要你点头的动作真的会停下来等你 | 只对声明了路径/URL/命令入参的工具生效 |
| 权限规则 | 特定路径、主机、命令前缀的收紧 | 只能收紧；`bash` 不受路径规则约束 |
| 网络出口名单 | 三个网络工具访问未授权主机 | 不拦 `bash` 里跑的 `curl`——它不是防火墙 |
| 凭据隔离 | agent 的文件工具读不到 `~/.volto`（密钥、配置） | 读边界不是工作区围栏：工作区外的文件原则上可读 |

## 明确不承诺的

- **不承诺防住被诱导。** 命令内容不做「危险命令」分类——那种「看起来挡得住」的错觉比不做更危险。
- **不承诺工作区围栏。** 读侧没有额外限制，能读全盘（凭据目录除外）。
- **不承诺网络全封。** 只有那三个网络工具经过名单。
- **不承诺完全档安全。** 「完全」等于无沙箱、无审批，只在完全信任任务时用。

## 所以该怎么用

1. **默认用「询问」档**，让人保持在回路里。
2. **别在装着生产凭据的目录里跑不可信的任务**——这是唯一可靠的做法，因为它不依赖任何机制的正确性。
3. **要看懂审批卡再点。** 卡上写的就是要执行的内容；看不懂就别放行。
4. **规则用来减少重复打扰**（`pnpm test` 之类），不要用它去「放宽」边界——它做不到。

完整威胁模型与逐项论证见仓库根目录的 [`SAFETY.md`](../../../SAFETY.md)。

## 代码智能与数据库的额外边界

语言服务器（`lsp_*`）与 sqlite（`db_query` / `db_exec`）各自有一条独立于 shell 的边界，值得单独说清：

- **语言服务器子进程受同样的沙箱约束，且默认封网**；凭据目录 `~/.volto` 不可读，`*API_KEY*` / `*TOKEN*` / `*SECRET*` 这类环境变量也会被剥掉。「完全」档下同样不隔离。
- **但读范围仍是全盘**（凭据目录除外），`lsp_hover` 与诊断在原理上可能带回工作区外文件的内容。
- **只读档下语言服务器写不了自己的缓存**，超大仓会变慢——这是隔离的代价。
- **在途请求不可取消**：超时（默认 15 秒）会回收该连接并杀掉子进程，下一次调用重新起一个，不会永久污染后续。
- **非 TS/JS 语言没有内置映射**，需要在 `lsp` 分区登记；未登记时调用返回可复制的配置片段，而不是构建失败。
- **sqlite 是进程内句柄，沙箱管不到它**，所以另有三层约束：库文件路径必须落在工作区内（realpath 校验，越界即拒）；`db_query` 用只读句柄，写语句由 SQLite 拒绝而不是靠文本预筛；显式拒绝 `ATTACH` / `DETACH` / `VACUUM INTO` / `load_extension`——这几条只读句柄拦不住，却都能绕开工作区去打开任意文件。
- **`db_exec` 只在宿主授予写权限时存在**：不允许写时它根本不注册，模型看不到它，而不是「看得见但必然被拒」。
- **`better-sqlite3` 是原生模块**：未安装时首次打开返回安装指引，不在构建期崩溃，也不静默降级。
