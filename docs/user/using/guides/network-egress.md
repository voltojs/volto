# 网络出口名单

> 读完你会：知道这份名单管住了什么、管不住什么，以及为什么它不能当防火墙。

## 它管住哪三个工具

`egress` 只作用于 **Network 端口**，目前接入它的只有三个工具：

- `web_fetch`
- `web_search`
- `http_query`

## 怎么配

`~/.volto/config.json` 的 `egress` 分区：

```json
{
  "egress": {
    "allowHosts": ["api.example.com", "docs.example.com"],
    "denyHosts": ["evil.example.net"]
  }
}
```

规则：

- **主机名精确匹配**，大小写不敏感；**没有通配符**——写 `*.example.com` 不会命中任何东西，它只会被当成一个字面量主机名。
- **denylist 优先**：同一主机同时在两个名单里，拒绝。
- **写了 `allowHosts` 就进入白名单模式**：不在名单里的主机一律拒绝。`"allowHosts": []` 是合法且有意义的值——拒绝全部。
- 只写 `denyHosts` 则是黑名单模式，其余主机放行。

## 被拒时看到什么

请求不会真正发出，工具返回一个结构化错误（HTTP 403 语义）并带上主机名。模型收到的是「被策略拒绝」，会换一种做法或直接告诉你。

## 什么时候生效

每次会话构建时重读，所以改动**对新会话生效**，不需要重启网关。

配置写坏（语法错、`allowHost` 少个 s、名单里混入非字符串）会**拒绝启动**，而不是悄悄放行。这是有意的：静默失效比报错危险。

## 它管不住什么

这段是重点，因为它决定了你能不能用它来「兜底」：

1. **模型自身的网络传输不经过它。** 模型请求由供应商适配器发出，跟这个名单无关。
2. **`bash` 里跑的进程完全不经过它。** `curl`、`npm install`、`git push` 都不受约束。
3. **它不是系统级防火墙。** 真要限制出站，得在容器/网络层做，不是在 agent 配置里做。

换句话说：**它约束的是「agent 主动联网查资料」这一条路径**，不是这台机器能不能上网。

## 沙箱内的网络

如果你开了沙箱隔离，沙箱内部还会按自己的网络设置决定是否允许出站。要在隔离环境里让网络工具走代理（TCP 桥接），需要系统里有 `socat`；缺失时会有明确警告，而不是静默降级。

## 出问题怎么办

- **访问一个明明存在的主机被拒** → 检查是不是白名单模式，以及主机名有没有多写路径（这里只写主机，不带 `https://`）。
- **改了配置没生效** → 只对新会话生效，新建一段会话。
- **网关起不来，报 egress 配置错** → 修 JSON；错误信息会指出哪个键、什么问题。
